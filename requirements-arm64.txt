# Locked native Windows ARM64 runtime.
#
# Kept separate from requirements.txt because packaging resolves these wheels from an x64
# build host, where environment markers would otherwise pick the wrong machine, and because
# the two architectures genuinely need different packages rather than the same list with
# different binaries.
#
# Fully resolved and transitive on purpose. `pip install --target` never runs setup.py, so
# nothing here gets installed on a dependency's behalf: an omitted transitive package is a
# missing module at runtime on a machine with no debugger attached. That is why entries like
# pycparser, h11 and anyio appear even though nothing in server/ imports them directly.
#
# Hash-locked so a rebuild either produces the same tree or fails loudly.
#
# What ARM does not get, and why:
#
#   ctranslate2 / faster-whisper   no win_arm64 wheel exists and upstream has said it will
#                                  not build one. Whisper runs through onnxruntime-genai
#                                  instead; server/engine.py already selects between them.
#   soxr                           no win_arm64 wheel. server/resample.py uses PyAV's
#                                  swresample, pinned to a 256-tap filter, which measures
#                                  78.8 dB on the project corpus against soxr HQ's 74.6 and
#                                  agrees with it to 0.00 dB across the speech band.
#   pyaudiowpatch                  no win_arm64 wheel, so system-audio loopback is NOT
#                                  available on ARM yet. server/app.py already treats
#                                  loopback as optional, so the picker simply lists no
#                                  output devices rather than failing. soundcard is pinned
#                                  below as the intended CFFI WASAPI replacement, but
#                                  nothing imports it yet - it is staged, not wired.
#   nvidia-*                       there is no CUDA on a Snapdragon.
#
# What ARM does get that x64 does not: onnxruntime-genai (the Whisper engine) and soundcard.
#
# sherpa-onnx publishes native win_arm64 wheels in two distributions - the pure-Python
# wrapper and sherpa-onnx-core, which carries ARM64 onnxruntime.dll, sherpa-onnx-c-api.dll
# and sherpa-onnx-cxx-api.dll. Both are pinned here, and between them they carry the
# streaming transducer engine AND speaker labelling, so neither is lost on ARM.
